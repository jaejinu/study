## 토큰이 화폐다

LLM API 는 **토큰** 단위로 청구한다. 그리고 토큰 종류마다 단가가 다르다(2026 년 공개가 근사, USD / 1M 토큰).

| 모델 등급 | 입력 | 캐시된 입력 | 출력 | 출력/입력 |
|---|---|---|---|---|
| 대형 (gpt-5 급) | $1.25 | $0.125 | $10 | 8배 |
| 중형 (gpt-5-mini 급) | $0.25 | $0.025 | $2 | 8배 |
| 소형 (gpt-5-nano 급) | $0.05 | $0.005 | $0.40 | 8배 |

세 가지가 보인다.

1. **출력이 입력보다 훨씬 비싸다.** 생성은 토큰 하나씩 순차 계산(decode)이고, 입력은 한 번에 병렬 계산(prefill)이기 때문이다.
2. **캐시된 입력은 90% 싸다.** 같은 앞부분(프리픽스)을 반복해 보내면 서버가 그 부분의 계산 결과(KV 캐시)를 재사용한다.
3. **등급 간 25배 차이.** 어떤 모델에 보내느냐가 가장 큰 레버다.

토큰·캐시·지연의 기본 구조는 [AI 시스템 — 프롬프트 캐시·비용·지연](/ai-systems/notes/05-prompt-cache-cost-latency)에서 다뤘다. 이 노트는 그것을 **비용 최적화 절차**로 정리하고 실제로 잰다.

## 도우미형 기능은 입력이 비용이다

"AI 에게 묻기" 처럼 문서를 근거로 답하는 기능의 요청 하나:

```
┌─────────────────────────── 입력 (수천 토큰) ───────────────────────────┐ ┌ 출력 ┐
│ 시스템 지시 │ 도구 정의 │ 노트 본문 / 검색 결과 (RAG) │ 대화 이력 │ 질문 │ │ 답변 │
│  고정       │  고정     │  페이지마다 고정            │  누적     │ 짧음 │ │ 수백 │
└─────────────────────────────────────────────────────────────────────┘ └──────┘
```

이 사이트에서 CDC 노트를 넣은 질문은 **입력 4,053 토큰, 출력 64 토큰**이었다(실험 `finops-llm-token-cost`). 출력 단가가 8배라도 입력이 60배 많으니 **비용의 약 90% 가 입력**이다. 그래서 최적화 순서는 입력부터다.

## 레버 1 — 프롬프트 캐시: 같은 앞부분을 다시 계산하지 않는다

모델은 입력 토큰마다 attention 의 Key·Value 를 계산한다(prefill). 앞부분이 같으면 그 KV 를 저장해 두고 재사용할 수 있다. 계산이 줄어드니 **지연(TTFT)도 줄고 가격도 할인**된다.

캐시가 맞으려면 **앞부분이 바이트 단위로 같아야** 한다. 그래서 프롬프트 배치 규칙:

| 순서 | 내용 | 이유 |
|---|---|---|
| 1 | 시스템 지시, 도구 정의 | 모든 요청에 공통 — 항상 적중 |
| 2 | 문서·노트 본문 | 같은 페이지 질문끼리 적중 |
| 3 | 대화 이력 | 턴이 늘어도 앞부분은 유지 |
| 4 | 이번 질문, 시각·사용자명 같은 가변값 | **맨 뒤에** — 앞에 두면 캐시가 매번 깨진다 |

> **함정:** 시스템 프롬프트 맨 앞에 "현재 시각: 2026-10-17 12:03:41" 를 넣으면 매 요청 프리픽스가 달라져 캐시가 **0%** 가 된다. 실험 `finops-llm-token-cost` 는 이걸 거꾸로 이용한다 — 실행마다 다른 값을 맨 앞에 넣어 첫 호출을 일부러 캐시 미스로 만든다.

제공자마다 방식이 다르다.

- **자동 캐시**(OpenAI 계열): 일정 길이(예: 1,024 토큰) 이상의 동일 프리픽스를 자동으로 캐시. 수 분~1시간 유지.
- **명시적 캐시**(Anthropic 계열): `cache_control` 로 경계를 지정. 쓰기는 약간 비싸고 읽기는 90% 할인. 이 사이트의 `/assistant` 가 이 방식이다.

## 레버 2 — 출력을 줄인다

출력 토큰은 비싸고 **느리다**(토큰마다 순차 생성). 실험에서 같은 프롬프트에 출력 상한을 64 → 256 으로 늘리자 전체 시간이 0.6초 → 1.7초가 됐다.

| 기법 | 방법 |
|---|---|
| 상한 | `max_tokens` / `max_output_tokens` 를 기능별로 (요약 200, 분류 5) |
| 형식 지시 | "3줄로", "표로", "근거 링크 2개만" |
| 구조화 출력 | JSON 스키마 강제 — 장황한 설명이 사라진다 |
| 추론 노력 조절 | 추론 모델의 reasoning effort 를 쉬운 작업에서 낮춤 (추론 토큰도 출력 요금) |
| 스트리밍 + 조기 중단 | 사용자가 멈추면 생성도 멈추기 (AskPanel 의 '중단' 버튼) |

## 레버 3 — 모델을 고른다 (라우팅·캐스케이드)

모든 질문에 대형 모델이 필요하지 않다.

```
질문 ──▶ 분류(규칙 또는 소형 모델) ──┬─ 쉬움 (정의·요약·링크 찾기) ──▶ 소형 모델
                                     └─ 어려움 (설계·디버깅·비교) ────▶ 대형 모델

캐스케이드: 소형으로 먼저 → 자신 없음/검증 실패 → 대형으로 재시도
```

실험의 측정 토큰으로 계산하면, 질문 80% 를 소형·20% 를 대형으로 보낼 때 요청당 비용은 **전부 대형일 때의 23%** 다. 품질은 평가 데이터셋으로 확인하며 비율을 조정한다([AI 시스템 — 평가](/ai-systems/notes/06-evaluation-guardrails-safety)).

## 레버 4 — 컨텍스트 다이어트

캐시로 싸게 만들기 전에 **애초에 덜 보낸다**.

| 기법 | 효과 |
|---|---|
| 노트 전문 대신 **검색 상위 k 청크** | 수천 → 수백 토큰 ([RAG 설계](/ai-systems/notes/03-rag-design)) |
| 대화 이력 요약·창 제한 | 긴 대화의 선형 증가 차단 (AskPanel 은 최근 16턴) |
| 도구 정의 최소화 | 안 쓰는 도구 제거, 설명 압축 |
| 중복 제거 | 같은 문서가 검색·시스템 프롬프트에 두 번 들어가지 않게 |

## 레버 5 — 배치와 응답 캐시

- **배치 API**: 즉시 답이 필요 없는 작업(퀴즈 생성, 노트 요약, 평가)을 모아 보내면 보통 **50% 할인**. 24시간 안에 결과.
- **응답 캐시**: 같은 질문(정규화 후)에는 저장된 답을 준다. Redis 에 `hash(model + prompt) → 답변` (TTL). 의미 유사 질문까지 묶으면 시맨틱 캐시 — 임베딩 비용과 오답 위험을 같이 본다.

## 비용 상한과 관측

토큰 비용은 **버그 하나로 폭주**한다(무한 툴 루프, 거대한 문서 첨부, 봇 트래픽). 방어선:

1. **요청당 상한**: 입력 토큰 상한(예: 20k), 툴 루프 최대 횟수(이 사이트는 5~6회).
2. **사용자·테넌트별 한도**: 하루 토큰/질문 수 — 토큰 버킷 레이트리밋([API 게이트웨이](/api-design/notes/06-gateway-auth-ratelimit)).
3. **예산 알림**: 시간당 비용이 평소의 3배면 알림.

```promql
# 시간당 LLM 비용 (USD) — 이 사이트가 남기는 메트릭
sum(rate(study_llm_cost_usd_total[1h])) * 3600

# 모델별 입력:출력 토큰
sum by (model, kind) (rate(study_llm_tokens_total[1h]))

# 이상 탐지: 지난 1시간 비용이 지난주 같은 시각의 3배
sum(rate(study_llm_cost_usd_total[1h])) > 3 * sum(rate(study_llm_cost_usd_total[1h] offset 1w))
```

## 예시로 보기 — 이 프로젝트에서

실험 `finops-llm-token-cost` 는 로컬 Ollama(qwen2.5:1.5b)로 토큰과 시간을 실제로 재고, 그 토큰으로 상용 단가를 계산한다. 이 Mac 에서 측정한 값:

| 경우 | 입력 토큰 | 출력 토큰 | prefill(ms) | 전체(ms) |
|---|---|---|---|---|
| 짧은 프롬프트 | 40 | 64 | 40 | 421 |
| 노트 프롬프트, 첫 호출 | 4,053 | 64 | 756 | 1,169 |
| 같은 노트, 두 번째 호출 (캐시) | 4,054 | 64 | **170** | 585 |
| 같은 노트, 출력 256 | 4,056 | 256 | 36 | 1,701 |

- 노트를 넣으면 입력이 **100배** 된다.
- 같은 프리픽스를 다시 보내자 prefill 이 **756 → 170ms (−78%)**. Ollama 는 토큰 수를 그대로 보고하지만 계산은 줄었다 — 상용 API 의 "캐시된 입력 90% 할인" 의 정체가 이 절감이다.
- 캐시 적중 상태에서 출력 상한을 64 → 256 으로 올리니 전체 시간이 0.6초 → 1.7초(약 3배)가 됐다. 생성은 토큰당 약 6ms 의 순차 작업이라 출력 길이에 거의 정비례한다.

하루 2,000 질문 가정의 월 비용(가정 단가):

| 모델 | 캐시 없음 | 프리픽스 캐시 | 캐시 + 출력 32 |
|---|---|---|---|
| gpt-5 | $342 | $71 | $52 |
| gpt-5-mini | $68 | $14 | $10 |
| gpt-5-nano | $14 | $2.8 | $2.1 |

이 사이트의 `/api/ask` 는 노트 본문을 시스템 프롬프트에 넣고 질문은 맨 뒤에 둔다 — 같은 노트에서 이어지는 질문은 자동 캐시에 적중하는 구조다. 다만 "관련 노트 검색 결과" 를 질문마다 다르게 붙이므로 그 부분부터는 캐시가 깨진다. 검색 결과를 질문 뒤로 옮기면 캐시 적중 구간이 길어진다 — 실제로 해 볼 만한 개선이다.
