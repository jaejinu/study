## 조용한 실패

웹 서비스가 고장 나면 5xx 가 쏟아지고 알림이 운다. ML 시스템이 고장 나면 **200 OK 로 틀린 답**을 낸다. 지연·에러율·CPU 대시보드는 전부 녹색이다.

- 추천 모델이 계절이 바뀌었는데 여름 상품을 계속 추천한다
- LLM 공급자가 같은 모델 이름으로 새 스냅샷을 배포했더니 JSON 형식 준수율이 97% → 82% 로 떨어졌다
- 검색 인덱스 갱신 배치가 멈춰서 RAG 가 3주 전 문서로 답한다

이런 실패는 **품질을 직접 재지 않으면** 사용자가 떠나고 나서야 안다. [SRE 의 SLI](/sre/notes/02-sli-slo-error-budget) 를 정의할 때 "성공한 요청" 의 기준에 품질을 넣어야 하는 이유다.

## 관측할 다섯 층

| 층 | 무엇을 | 예 (LLM 기능) | 도구 |
|---|---|---|---|
| 인프라 | GPU/CPU·메모리·큐 길이 | 서빙 대기열 길이, KV 캐시 사용률 | Prometheus |
| 요청 | 지연·에러·처리량·비용 | TTFT·TPOT, 토큰·비용, 429 비율 | [LLM 관측](/observability/notes/08-llm-observability) |
| 입력 | 들어오는 데이터의 분포 | 질문 길이, 언어, 주제 분포, 검색 결과 수 | 로그 + 배치 분석 |
| 출력 | 모델이 낸 것의 분포 | 답변 길이, 거절률, 형식 준수율, 인용 포함률 | 로그 + 규칙 검사 |
| 결과 | 실제로 맞았나 | 👍/👎, 재질문율, 작업 완료율, 샘플 판사 점수 | 피드백·온라인 평가 |

인프라·요청 층은 [관측성](/observability) 의 일반 도구로 충분하다. ML 관측의 핵심은 **입력·출력·결과** 세 층이다.

## 드리프트의 종류

| 종류 | 정의 | 예 | 모델 자체는 |
|---|---|---|---|
| **데이터(공변량) 드리프트** | 입력 분포 P(X) 가 변함 | 신규 주제(eBPF) 질문이 급증 | 그대로지만 낯선 입력이 많아짐 |
| **개념 드리프트** | 입력과 정답의 관계 P(Y\|X) 가 변함 | "최신 Redis 버전" 의 정답이 7 → 8 로 바뀜 | 예전 정답을 계속 냄 |
| 라벨 드리프트 | 정답 분포 P(Y) 가 변함 | 스팸 비율이 2% → 20% | 임계값이 안 맞게 됨 |
| **공급자 드리프트** | API 모델의 동작이 변함 | 같은 이름의 모델 업데이트 | 우리가 모르게 바뀜 |
| 파이프라인 드리프트 | 전처리·검색이 변함 | 인덱스 갱신 중단, 토크나이저 버전 | 입력이 망가져서 들어옴 |

공급자 드리프트는 LLM 시대에 새로 생긴 위험이다. 대응: **날짜가 고정된 모델 스냅샷 이름**을 쓰고, 버전을 바꿀 때는 골든셋 회귀 평가([노트 07](/mlops/notes/07-eval-ci-prompt-regression))를 통과해야 한다.

## 드리프트 탐지 통계

기준 분포(학습 시점 또는 지난주)와 현재 분포를 비교한다.

### PSI (Population Stability Index)

값을 구간(bin)으로 나누고 구간별 비율을 비교한다.

```
PSI = Σ (현재% − 기준%) × ln(현재% / 기준%)
```

| PSI | 해석 |
|---|---|
| < 0.1 | 변화 없음 |
| 0.1 ~ 0.25 | 약간 변화 — 관찰 |
| > 0.25 | 큰 변화 — 조사 |

예: 질문 길이 구간 [짧음 50%, 보통 35%, 긺 15%] → 이번 주 [30%, 40%, 30%]

```
(0.30−0.50)·ln(0.30/0.50) + (0.40−0.35)·ln(0.40/0.35) + (0.30−0.15)·ln(0.30/0.15)
= 0.102 + 0.007 + 0.104 = 0.213   → 약간 변화
```

### 그 밖의 방법

| 방법 | 대상 | 특징 |
|---|---|---|
| KS 검정 | 연속 값 하나 | 표본이 크면 사소한 차이도 "유의" — 효과 크기와 같이 본다 |
| 카이제곱 | 범주 분포 (주제·언어) | 범주가 많으면 희소 문제 |
| **임베딩 거리** | 텍스트 입력 전체 | 질문 임베딩의 평균·클러스터 분포를 비교 — LLM 입력에 가장 유용 |
| 규칙 지표 | 형식 준수율, 거절률 | 해석이 쉬워 알림에 적합 |

드리프트 = 장애가 아니다. 새 주제가 늘어난 것은 사업이 잘 되는 신호일 수도 있다. 드리프트 알림은 **"골든셋이 아직 현실을 대표하는가" 를 다시 보라는 신호**로 쓰고, 품질 지표가 함께 나빠질 때만 페이지를 울린다.

## 정답 없이 품질을 추정하기

결과 층의 정답(사용자가 만족했나)은 늦게, 드물게 온다. 그 사이를 대리 지표로 메운다.

| 대리 지표 | 측정 | 의미 |
|---|---|---|
| 형식 준수율 | JSON 파싱 성공, 필수 필드, 링크 형식 | 가장 신뢰할 수 있음 — 즉시·결정적 |
| 거절률 | "모르겠습니다", 안전 거절 | 급증하면 프롬프트·모델 변경 의심 |
| 근거 인용률 | 답변에 출처(노트 링크)가 있나 | RAG 품질 |
| 검색 0건 비율 | 검색 결과가 비어 모델이 맨손으로 답한 비율 | 인덱스·검색 품질 |
| 답변 길이 분포 | 평균·p95 | 갑자기 길어지거나 짧아지면 동작 변화 |
| 재질문율 | 같은 세션에서 비슷한 질문 반복 | 첫 답이 불만족 |

## 사용자 피드백과 그 편향

👍/👎 는 소중하지만 편향이 심하다.

| 편향 | 내용 | 대응 |
|---|---|---|
| 선택 편향 | 피드백을 누르는 사용자는 1~5%, 대개 불만족한 사람 | 비율이 아니라 **추이**를 본다 |
| 지연 | 결과(작업 성공)는 나중에 안다 | 대리 지표와 결합 |
| 피드백 루프 | 👍 받은 답 스타일로 학습하면 그 스타일만 강화 | 탐색 유지, 사람 라벨 표본 |
| 기준 불일치 | 사용자는 "친절함" 에, 우리는 "정확성" 에 관심 | 피드백 사유(정확하지 않음/너무 김) 수집 |

## 온라인 평가 — 샘플링 + 판사

실제 트래픽의 1~5% 를 샘플링해 **오프라인과 같은 판사**로 채점하고 시계열로 남긴다.

```
요청 로그 (질문, 검색된 노트, 답변, 모델·프롬프트 버전)
  └─ 1% 샘플 → 판사: "답이 검색된 노트에 근거하는가? (예/아니오)"   ← 근거성(groundedness)
             → 형식 검사: 노트 링크 포함?
  └─ 결과를 메트릭으로: study_ask_grounded_ratio{prompt_version="v3"}
```

판사도 틀린다. 실험 [`mlops-eval-harness`](/mlops/lab/mlops-eval-harness) 에서 작은 판사는 순서만 바꿔도 22% 판정이 뒤집혔고, 자기 답을 78% 일관되게 골랐다. 온라인 판사는 **강한 모델**로, 주기적으로 사람 라벨과 일치율을 확인한다([평가 노트](/mlops/notes/02-eval-datasets-metrics)).

## 가드레일 — 실패를 막는 마지막 층

관측은 사후에 알려 주고, 가드레일은 그 자리에서 막는다.

| 위치 | 검사 | 실패 시 |
|---|---|---|
| 입력 | 길이 제한, PII 감지·마스킹, 프롬프트 인젝션 패턴 | 거절 또는 정제 |
| 검색 | 결과 0건, 낮은 유사도 | "자료가 없다" 고 답하게 (지어내지 않게) |
| 출력 | JSON 스키마 검증, 금칙어, 링크가 실제 존재하는 노트인지 | 재시도(1회) → 대체 응답 |
| 행동 | 툴 호출 승인 (실험 실행은 사용자 승인) | 사람에게 넘김 |

출력 검증 실패 시 **무한 재시도는 금물**이다. 1회 재시도 후 안전한 대체 응답, 그리고 실패를 메트릭으로 센다. [보안 노트](/security/notes/08-web-api-llm-security) 의 프롬프트 인젝션·툴 권한과 같은 층이다.

## 알림 설계

| 알림 | 조건 | 심각도 |
|---|---|---|
| 형식 준수율 하락 | 1시간 준수율 < 95% (기준 99%) | 페이지 — 기능이 깨졌다 |
| 근거성 하락 | 일 단위 샘플 판사 근거율이 기준 대비 −10%p | 티켓 |
| 입력 드리프트 | 질문 임베딩 PSI > 0.25 | 티켓 — 골든셋 갱신 검토 |
| 검색 0건 급증 | 1시간 0건 비율 > 20% | 페이지 — 인덱스 장애 의심 |
| 비용 급증 | 시간당 비용 > 예산의 2배 | 페이지 |

[번레이트 알림](/sre/notes/03-burn-rate-alerting) 의 원리를 품질 SLO 에도 그대로 쓸 수 있다: "근거 있는 답변 비율 ≥ 95%" 를 SLO 로 두고 에러 버짓 소진 속도로 알린다.

## 예시로 보기 — 이 프로젝트에서

AI 에게 묻기(`/api/ask`)는 이미 요청 층 지표를 남긴다: `study_llm_tokens_total`, `study_llm_cost_usd_total`, `study_llm_latency_seconds{phase="ttft"|"total"}`, `study_llm_tool_calls_total`, 그리고 구조화 로그 `ask.chat`(모델·토큰·비용·지연·경로). 빠진 것은 출력·결과 층이다. 추가한다면:

```ts
// 응답이 끝난 뒤 (route.ts 의 usage 이벤트 근처)
const links = [...text.matchAll(/\]\((\/[a-z0-9-]+\/notes\/[a-z0-9-]+)\)/g)].map((m) => m[1]);
const valid = links.filter((href) => noteExists(href));            // 존재하는 노트만
metrics.askCitations.inc({ model, has_citation: links.length ? "yes" : "no" });
metrics.askBrokenLinks.inc({ model }, links.length - valid.length); // 환각 링크
metrics.askOutsideSite.inc({ model, flagged: /사이트 밖 내용/.test(text) ? "yes" : "no" });
```

- **인용률**: 근거 링크가 있는 답변 비율 — 검색 증강이 작동하는가
- **환각 링크**: 존재하지 않는 노트 링크 수 — 작은 모델이 slug 를 지어내는지
- **사이트 밖 표시율**: 프롬프트 규칙 준수

이 세 지표만 있어도 모델을 qwen 1.5B 에서 gpt-5-mini 로 바꿀 때 품질 차이를 숫자로 비교할 수 있다.

> 함께 읽기: 관측이 다음 데이터가 되는 순환은 [ML 시스템 생애주기](/mlops/notes/01-ml-system-lifecycle) 의 6 → 2 화살표다.
