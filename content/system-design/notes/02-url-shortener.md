## 요구사항과 숫자

- 기능: 단축 생성, 리다이렉트, 클릭 통계(선택).
- 비기능: 리다이렉트 p99 < 50ms, 99.99%, 코드 추측 어려움, 10년 보관.
- 숫자(하루 신규 1억 기준): 쓰기 1,000/s, 읽기 100,000/s(피크 30만), 10년 3.65×10¹¹ 개 → **코드 7자**(62⁷ ≈ 3.5×10¹²). 계산 과정은 [노트 01](/system-design/notes/01-design-method).

## 코드를 어떻게 만들까

| 방식 | 충돌 | 길이 | 예측 | 분산 |
|---|---|---|---|---|
| 전역 카운터 + base62 | 없음 | 최소 | **쉬움** (1001, 1002, …) | 카운터가 단일점 |
| 범위 할당 카운터 | 없음 | 최소 | 서버별 범위 내에서 쉬움 | 서버가 블록(예: 100만 개)을 받아 로컬 증가 |
| 해시(URL) 앞 n 자 | **있음** | n | 어려움 | 좋음 |
| 랜덤 n 자 | 있음 | n | 어려움 | 좋음 |
| 카운터 + 순열(Feistel·곱셈 역원) | 없음 | 최소 | 어려움 | 범위 할당과 결합 |

### 실측 — 해시 충돌과 생일 문제

[sd-url-shortener](/system-design/lab/sd-url-shortener) 에서 URL 5만 개를 SHA-256 → base62 로 바꿔 앞 n 자만 썼다.

| 코드 길이 | 공간 | 실제 충돌 | 기대값 n²/(2·62ᴸ) |
|---|---|---|---|
| 4자 | 1,480만 | **84** | 84.6 |
| 5자 | 9억 1,600만 | 2 | 1.4 |
| 6자 | 568억 | 0 | 0.0 |

공간이 1,480만인데 5만 개만 넣어도 충돌이 84개다 — **생일 문제**: 충돌 확률은 n/공간 이 아니라 n²/공간 에 비례한다. 그래서 해시 방식은 "충돌이면 소금(salt)을 바꿔 재시도" 와 길이 여유가 필요하고, 저장소에 `code` 유일 제약이 반드시 있어야 한다.

카운터 방식은 같은 실험에서 INCR 5만 번(파이프라인)이 63ms, 충돌 0, 코드는 `1001, 1002, 1003…` 이었다. 충돌이 없는 대신 **다음 링크를 추측할 수 있다**. 비공개 링크가 있는 서비스라면 치명적이다.

### 권장 조합

```ts
// 1) 서버는 카운터 블록을 받는다: INCRBY url:block 1000000 → [n, n+1,000,000)
// 2) 블록 안에서 로컬 증가 (Redis 왕복 없음)
// 3) 번호를 섞는 전단사 함수로 예측을 막는다 (같은 공간 안의 순열)
const scramble = (n: bigint) => (n * MULT + ADD) % SPACE;  // MULT 와 SPACE 서로소
const code = base62(scramble(n)).padStart(7, "0");
```

블록 방식은 서버가 죽으면 블록 일부를 버린다(빈 번호) — 괜찮다. 코드가 연속일 필요는 없다.

## 리다이렉트 경로 — 읽기 30만 QPS

```
브라우저 ─▶ CDN(엣지 캐시, 302 도 캐시 가능하게 짧은 TTL) ─▶ API ─▶ 프로세스 메모리 LRU ─▶ Redis ─▶ DB
```

### 실측 — 캐시가 왜 효과가 큰가

같은 실험에서 링크 조회 2,000회(순차):

| 경로 | p50 | p99 |
|---|---|---|
| PostgreSQL 기본 키 조회 | 0.234ms | 1.209ms |
| Redis GET | 0.166ms | 1.192ms |

로컬에서는 차이가 작아 보이지만, DB 는 **동시 부하**에서 연결 수·CPU 한계에 먼저 닿는다. 캐시의 가치는 지연보다 **DB 를 보호하는 것**에 있다.

그리고 링크 인기는 고르지 않다(지프 분포). 20만 요청으로 LRU 캐시 크기별 적중률을 계산했다.

| 캐시 크기 (전체 5만 링크 대비) | 적중률 |
|---|---|
| 500 (1%) | 44.9% |
| 2,500 (5%) | 62.5% |
| 5,000 (10%) | 70.2% |
| 25,000 (50%) | 85.0% |

링크의 1% 만 캐시해도 요청의 거의 절반이 맞는다. 인기 쏠림이 클수록 작은 캐시가 효과적이다 — 이것이 다층 캐시(CDN → 메모리 → Redis)의 근거다. 캐시 무효화·스탬피드 대책은 [Redis 노트 08](/redis/notes/08-caching-patterns)과 실험 [cache-stampede](/redis/lab/cache-stampede).

## 쓰기 경로와 데이터

```sql
create table links (code text primary key, url text not null, created_at timestamptz, owner_id bigint, expires_at timestamptz);
create unique index on links (md5(url)) where owner_id is null;   -- 익명 단축의 중복 방지
```

- 10년 3.65×10¹¹ 행 → 한 대에 안 들어간다. `code` 해시로 샤딩하거나 키-값 저장소(DynamoDB·Cassandra).
- 만료된 링크 정리는 파티션 단위 삭제가 싸다(기간 파티셔닝 — [PostgreSQL 노트 06](/postgres/notes/06-partitioning-scale)).

## 클릭 통계 — 리다이렉트를 느리게 하지 마라

리다이렉트 응답 경로에서 DB 에 `update clicks = clicks + 1` 을 하면 인기 링크 하나가 행 잠금 경합점이 된다.

```
리다이렉트 ─▶ (비동기) 클릭 이벤트 ─▶ Kafka ─▶ 1분 집계 ─▶ ClickHouse
```

정확한 순방문자 수는 HyperLogLog 로 근사한다(실험 [hyperloglog](/redis/lab/hyperloglog)). 집계·분석은 [ClickHouse 노트 04](/clickhouse/notes/04-materialized-views-aggregation).

## 장애와 남용

| 시나리오 | 대책 |
|---|---|
| 캐시 장애로 DB 직격 | 요청 병합(single-flight), 부하 차단, CDN 이 버팀 |
| 피싱·악성 URL 단축 | 생성 시 평판 검사, 신고 시 즉시 비활성(캐시 무효화 포함) |
| 생성 API 남용 | 레이트리밋([노트 03](/system-design/notes/03-rate-limiter)), 캡차 |
| 코드 열거 공격 | 순열·길이 여유·접근 레이트리밋 |

> 같은 "인기 쏠림 → 작은 캐시로 큰 적중률" 원리가 [검색 자동완성](/system-design/notes/07-search-autocomplete)의 짧은 접두사 캐시에도 그대로 쓰인다.

## 심화 — 순열과 base62 를 코드로

"카운터 + 순열" 은 말로는 쉽지만, 공간 크기와 서로소 조건을 틀리면 코드가 겹친다. 7자 base62 공간은 62⁷ = 3,521,614,606,208 이다.

```ts
const ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ";
const SPACE = 62n ** 7n;                       // 3.5조
const MULT = 2_654_435_761n;                   // SPACE(=2⁷·31⁷)와 서로소: 2 와 31 의 배수가 아니면 된다
const ADD = 1_234_567_891n;

const scramble = (n: bigint) => (n * MULT + ADD) % SPACE;  // 0..SPACE-1 의 전단사 → 충돌 없음

function base62(n: bigint): string {
  let s = "";
  do { s = ALPHABET[Number(n % 62n)] + s; n /= 62n; } while (n > 0n);
  return s.padStart(7, "0");
}
// base62(scramble(1001n)), base62(scramble(1002n)) → 연속 번호인데 결과는 무관해 보인다
```

- 곱셈 순열은 **충돌이 없지만 암호학적으로 안전하지 않다**. 연속 코드 두 개를 알면 MULT 를 역산할 수 있다. 비공개 링크라면 Feistel 네트워크(라운드 함수에 HMAC)나 블록 암호 기반 형식 보존 암호화(FPE)를 쓴다.
- 대소문자를 구분하는 base62 는 사람이 받아 적을 때 `l/1/I`, `O/0` 이 헷갈린다. 사람이 읽는 코드라면 base58(비트코인 주소 방식)이나 Crockford base32 를 고려한다 — 길이가 조금 늘어나는 대가다.

### 데이터 저장소 선택의 실제 수치

| 선택 | 3.65×10¹¹ 행에서 | 비고 |
|---|---|---|
| 샤딩된 PostgreSQL | 샤드 64개 × 약 57억 행, 샤드당 수 TB | 운영 역량이 있으면 강력, 재샤딩이 숙제 |
| DynamoDB | 파티션 키 = code, 조회 한 자릿수 ms | 용량 모드·핫 파티션(인기 링크) 주의 — 캐시로 흡수 |
| Cassandra | code 해시로 고르게 분산, 쓰기 강함 | 범위 질의(소유자별 링크 목록)는 별도 테이블 |

소유자별 "내 링크 목록" 은 `code` 샤드와 접근 패턴이 다르다. `(owner_id, created_at)` 로 된 **두 번째 테이블(또는 인덱스 서비스)** 을 비동기로 채우는 것이 보통이다 — 하나의 키로 두 접근 패턴을 동시에 만족시키려 하지 않는다.

## 모니터링·로그 — 무엇을 보면 장애가 먼저 보이나

| 신호 | 정상 | 이상 징후와 원인 후보 |
|---|---|---|
| 리다이렉트 p99 | < 50ms | p50 정상 + p99 상승 → 캐시 미스 경로(DB 샤드 하나), GC |
| 계층별 적중률 (CDN / 로컬 LRU / Redis) | 예: 60% / 50% / 90% | Redis 적중률 급락 → 배포 후 키 접두사 변경, 메모리 eviction |
| 404 비율 | 낮고 안정 | 급등 → 코드 열거 공격(스캐너) 또는 깨진 캠페인 링크 |
| 생성 API 의 충돌 재시도 수 | 해시 방식에서 ≈ 0 | 증가 → 공간이 차는 중, 길이를 늘릴 때 |
| 카운터 블록 할당 속도 | 일정 | 급증 → 서버 재시작 반복(블록 낭비), 생성 남용 |
| 클릭 이벤트 Kafka lag | 수 초 | 증가 → 통계 지연(리다이렉트에는 영향 없음 — 분리가 맞았다는 증거) |

로그 한 줄의 예:

```json
{"ts":"2026-10-17T09:12:03Z","route":"redirect","code":"aZ3kP9x","status":302,
 "cache":"redis_hit","shard":17,"latency_ms":3.4,"trace_id":"4bf9…","ua_class":"bot"}
```

`cache` 필드가 있으면 "느린 요청은 전부 miss 였다" 를 바로 확인할 수 있다. `ua_class` 로 봇 트래픽을 분리하지 않으면 통계와 캐시 정책이 봇에게 끌려간다. 404 를 IP·ASN 별로 집계하면 열거 공격이 보인다 — [보안 노트 08](/security/notes/08-web-api-llm-security).

## 흔한 실수와 오해

- **"해시면 충돌이 없다"** — 해시 전체(256비트)는 사실상 없지만, 앞 n 자로 자르는 순간 생일 문제가 그대로 적용된다. 4자·5만 개에서 84개.
- **"301 이 더 빠르니 301"** — 브라우저가 영구 캐시해 통계가 사라지고, 링크 대상을 바꾸거나 악성 링크를 차단해도 이미 캐시한 브라우저에는 반영되지 않는다.
- **"캐시는 나중에"** — 읽기 30만 QPS 에서는 캐시가 DB 를 보호하는 필수 부품이다. 캐시 장애 = DB 장애.
- **링크 차단 시 캐시를 잊는다** — DB 만 비활성화하면 CDN·로컬 LRU·Redis 에 남은 사본이 계속 리다이렉트한다. 차단은 **모든 층의 무효화**(또는 짧은 TTL)와 함께.
- **URL 정규화 없이 중복 방지** — `https://a.com/x`, `https://A.com/x/`, `?utm=` 붙은 주소가 다른 링크가 된다. 중복 방지를 원하면 정규화 규칙을 먼저 정한다.

## 스스로 점검

1. **100만 개 코드를 만들 때 충돌 기대값이 1 미만이 되는 최소 base62 길이는?** — n²/(2·62ᴸ) < 1 → 62ᴸ > 5×10¹¹ → L = 7 (62⁶ ≈ 5.7×10¹⁰ 은 부족).
2. **곱셈 순열에서 MULT 가 SPACE 와 서로소여야 하는 이유는?** — 서로소여야 모듈러 역원이 있어 전단사가 되고, 서로 다른 n 이 같은 코드로 가지 않는다.
3. **인기 링크 하나가 DynamoDB 파티션 한도를 넘으면?** — 로컬 LRU·CDN 으로 흡수, 필요하면 키 복제(`code#0..N`)로 읽기 분산.
4. **리다이렉트가 정상인데 클릭 통계가 1시간 늦다. 어디부터 보나?** — Kafka 소비자 lag, 집계 잡 상태, ClickHouse 삽입 오류. 리다이렉트와 분리된 비동기 경로이므로 사용자 영향은 없다.
